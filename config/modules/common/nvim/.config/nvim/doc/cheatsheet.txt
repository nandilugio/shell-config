*cheatsheet.txt*   The keys of this config, and how to find the rest

                                                                  *cheatsheet*
<leader>? shows this in a float; `:help cheatsheet` opens it as any help.

    g jumps · gr acts on symbols · <leader> opens tools · [ ] iterate
    <C-w> windows

==============================================================================
GETTING HELP                                                *cheatsheet-help*

Four layers, each one deeper than the last:

<leader>, wait      which-key lists what can follow; <BS> goes back one key.
                    The bracketed letter is the mnemonic: [F]iles is f.
<leader>?           this file: gO outlines it, / searches it, q closes it.
K                   on any key or word here, its help page. <C-]> follows a
                    |link|, <C-o> comes back, q closes.
<leader>fh          search every help file, plugins included
<leader>fk          search every mapping, with its description

:help cheatsheet-git       jump to a section of this file
:help config.txt           the config's own manual (|review-mode|)
:checkhealth config        what is missing on this machine, and what it costs
:FzfLua <Tab>, :Gitsigns <Tab>, :Review <Tab>    what a command offers

------------------------------------------------------------------------------
HOW THE KEYS ARE ORGANISED                                  *cheatsheet-keys*

Namespaces, not plugins: <leader>g is git whatever provides it.

g        jumps: gd gD gy gI definitions, gg G, gv, gi    Vim's own prefix
gr       acts on the symbol under the cursor: grn gra grr grx    LSP
<leader> tools, by domain:
           f  find        g  git        u  toggle (ui)    x  lists
           o  own, reserved for keys of mine        ?  this cheatsheet
           e  explore files  =  format   - |  split   <leader><leader> buffers
,        <LocalLeader>: the current filetype's own keys (,t ,pt)
[ ]      previous, next: ]d diagnostic ]c change ]q quickfix ]b buffer
z        folds (and Vim's scrolling and spelling under the same letter)
<C-w>    windows, as Vim ships them; <C-hjkl> move between them

Alt is tmux's: M-a prefix, M-hjkl panes, M-1..9 windows. Nothing here uses it.

------------------------------------------------------------------------------
READING A MNEMONIC                                     *cheatsheet-mnemonics*

Capital = wider scope       gb blames the line, gB the file; gs stages the
                            hunk, gS the buffer; fs symbols here, fS anywhere;
                            gq this file's hunks to quickfix, gQ every file's
Capital because the         uH heading colours (uh is hints), uR review mode
lowercase was taken         (ur is relative numbers), zS shuts a fold (zs
                            scrolls sideways); f. and f? have no letter
Doubled = the current one   grr references, gcc comment, dd yy cc on the line
mask / reveal               zm zr fold one more level away, bring one back;
                            zM zR all of them. Not Vim's "fold more/less"
change, hunk                git's word for one contiguous change; ]c walks
                            them, ih is one as a text object
trace                       gt, the history of a function as it moved
own                         <leader>o: nothing else may ever claim it

VIM ITSELF                                                   *cheatsheet-vim*

Motions take a count and work in visual mode. Operators take a motion, and
doubled apply to the line: dd yy cc >> ==.

w,e,b  W,E,B    word, end, back                 0,^,$  start, first char, end
f,t {c}  ;  ,   find, till a char; repeat       {,}  paragraph   %  bracket
gg,G  {n}G      file start, end, line n         H,M,L  screen top, mid, bottom
*,#  n,N        search the word under cursor; next, previous match
<C-d>,<C-u>     half page      <C-f>,<C-b>  full page      zz,zt,zb  cursor to
<C-o>,<C-i>     back, forward through the places you jumped from

d c y  > < =    delete, change, yank; indent, dedent, reindent
                what you yank flashes, so you can see what it took
gu gU g~        lower, upper, swap case         gq  format
x s  p P        delete, substitute a char; put after, before
v V <C-v>       visual char, line, block        gv  reselect
gcc, gc         comment the line, the selection

Text objects, after an operator: diw ca( yip
iw,aw  i(,a(    word; brackets, also { [ < " ' `       ip,ap  paragraph
it,at           html tag                               in,an  syntax node
ih              git hunk (dih, yih)

:%s/old/new/gc  whole file, confirming each     :'<,'>s/...  the selection
:%s//new/g      an empty pattern reuses the last search

CODE                                                        *cheatsheet-code*

Everything here asks the language server; without one it says so.

gd,gD           definition, declaration         gy,gI  type, implementation
<C-]> / <C-t>   definition via tags / back      <C-o>,<C-i>  back, forward
K               hover; K again enters it, <Esc> or q closes
<C-s>           signature help, while typing arguments
gO              outline: the symbols of this file

grn             rename                          gra  code action
grr             references, into quickfix       grx  execute codelens
gq {motion}     format                          <leader>=  buffer or selection

grr finds what the server can resolve. For a metaprogrammed name or a word in
a comment, grep instead: <leader>fw or <leader>fg. The pickers <leader>fs and
<leader>fR show the same as gO and grr, in a picker rather than a list.

COMPLETION AND THE COMMAND LINE                       *cheatsheet-completion*

Neovim's own, and it never appears by itself: you ask for it. Nothing is
selected when the menu opens, so Enter still gives a newline until you pick.

<C-n>,<C-p>     open the menu, then next, previous
<C-y>           accept; also expands the snippet and adds the import
Enter           accept, but only once something is selected
<C-e>, <Esc>    dismiss, keeping what you typed; Esc again leaves insert
<C-x><C-o>      language server only            <C-x><C-f>  file paths
<Tab>,<S-Tab>   next, previous snippet placeholder
<C-Space>       as in VS Code and Zed, where the terminal lets it through

The command line is the same idea, on <Tab>:

Tab             open the menu, then next match  <S-Tab>  previous
<C-n>,<C-p>     with the menu open, next and previous, as in insert mode;
                with it closed, newer and older commands from history
<C-y>           accept the match and keep editing, to build up arguments
Enter           accept and run                  <C-e>  dismiss the menu
<Down>,<Up>     with the menu open, into and out of a directory;
                with it closed, command history, never the menu
<C-r><C-w>      insert the word under the cursor   <C-r>{reg}  a register
<C-f>           edit the command line as a buffer  q:  history as a buffer

]d,[d  ]D,[D    diagnostic; last, first         ]e,[e  ]w,[w  error, warning
]c,[c           change (git hunk)               ]q,[q  ]Q,[Q  quickfix
]b,[b           buffer                          ]<Space>,[<Space>  blank line
]v,[v           commit under review             ]a,[a  argument list

FILES, BUFFERS AND WINDOWS                               *cheatsheet-buffers*

A file is read into a buffer, and a window shows a buffer. Leaving a buffer
keeps it loaded, edits and all. There is no closing a file, only its buffer:
after :bd it is just on disk again. :q closes a window, and the last window
takes Neovim with it, since buffers alone keep nothing on screen. Unsaved
edits ask before they are lost, hidden buffers included.
The pickers and the browser open files (|cheatsheet-pickers|,
|cheatsheet-files|); this is what happens to them afterwards.

<leader>ff,fr   find a file, a recent one       <leader>e  browse from here
:e {path}       by name, Tab completes it       gf  the path under the cursor
<leader><leader> switch buffer, recent first    <C-x> there closes one
]b,[b           next, previous buffer           <C-^>  the one you came from
:b cfg<Tab>     by name, fuzzy, recent first    :ls  list them

:enew  :new     an empty buffer here, in a split; :w ++p {path} names it
:w  :wa         write this one, all of them     <leader>ua  autosave
:e!             drop the edits, reload          :w {name}  a copy; stay here
:bd             close the buffer; the file is just on disk again
:q              close the window; the last one leaves Neovim
:qa  :wqa       leave, leave writing everything ZZ  write, close this window

<C-h,j,k,l>     move between windows            tmux uses M-h,j,k,l for panes
<leader>-  |    split below, right              as in tmux
<C-w>           c close · o only · = equalise · _ | maximise

QUICKFIX                                                *cheatsheet-quickfix*

Vim's list of places. Filled by :make (rubocop, for ruby), :grep, M-q in a
picker, <leader>xd and the git keys gq gQ.

]q,[q           next, previous                  <leader>xq  open    :cclose
<CR>            jump to the entry under the cursor
The location list is the same, per window: ]l,[l and <leader>xl.

------------------------------------------------------------------------------
FOLDS                                                      *cheatsheet-folds*

A closed fold still shows its first line, colours and all: close everything
and the file reads as an outline. The cursor is never on a hidden line: a
fold closing around it puts it on the fold's first line, and every key acts
on the folds containing that line. |fold-commands| has the rest.

zc zo za        close, open, toggle the fold here; zc again, the one around it
zC              close it and every fold around it, out to the top level
zO              open it and everything inside it
zS              shut it: closed, and everything inside closed too (ours)
zm zr           mask, reveal one more level        zM zR  mask, reveal all
zn              no folding at all                  zN     bring it back

A fold reopens as it was when it closed: zC leaves the insides alone, zS
resets them, so zo after zS shows one level at a time. zm and zr set
'foldlevel' for the whole window, discarding every fold opened or closed by
hand. It starts at 99, so zm seems to do nothing at first: zM first, then
zr. Closing a fold shows the fold column (+ closed); zR and zn hide it
again, <leader>uz toggles it.

------------------------------------------------------------------------------
GETTING OUT                                                  *cheatsheet-out*

<Esc>           close a float or picker, else clear the search highlight
<Esc><Esc>      leave terminal mode
q               close the file browser, the cheatsheet, any help, a hover
                you entered, the git windows
<C-o>           jump back to where you came from

PLUGINS                                                  *cheatsheet-plugins*

browser. Without the tool, <leader>f* fall back to :find and :grep.

------------------------------------------------------------------------------
PICKERS                                                  *cheatsheet-pickers*

The input line is a text field, so move with Ctrl, not h j k l. These are
fzf's own keys, so they are the same ones the shell's fzf uses.

<C-j>,<C-k>     next, previous                  Enter  open
<C-s>,<C-v>     open in a split, a vsplit       <C-t>  in a tab
<C-f>,<C-b>     half page down, up              <C-u>  clear the query
<S-Up>,<S-Down> scroll the preview              <C-a>,<C-e>  query start, end
Tab             tick one, M-a M-a ticks all     M-q    ticked to quickfix
F1 help · F4 hide the preview · M-i include ignored · M-f follow symlinks

Tab does nothing in the file history, where a pick must be single.
Elsewhere Enter with several ticked sends them to quickfix, as M-q does; in
the buffers picker <C-x> closes the ticked ones.
M-a is the tmux prefix, so it has to be pressed twice to get through. M-h
(include hidden) is tmux's pane-left and never arrives; M-i is the one you
want anyway, since .gitignore hides more here than dotfiles do.

<leader><leader> buffers                        <leader>ff  files
<leader>fg      grep the project                <leader>fw  word under cursor
<leader>fr      recent files                    <leader>fh  help
<leader>fk      keymaps                         <leader>fd  diagnostics
<leader>fs,fS   symbols: file, workspace        <leader>fR  references, usages
<leader>f?      every picker fzf-lua has        <leader>f.  resume the last

------------------------------------------------------------------------------
FILE BROWSER                                               *cheatsheet-files*

<leader>e opens it. A normal buffer: edit a line to rename, delete a line to
delete, = to apply. Deletes go to a trash directory, so a mistaken = is
recoverable. |MiniFiles| has the rest.

l / L           enter, or open the file and stay / and close the browser
h / H           parent directory / parent, closing this column
=               apply pending changes           g?  help
m / '           set a mark / jump to it         @   reveal the working dir

GIT                                                          *cheatsheet-git*

Hunks and history here; commits and rebases belong in a tmux pane.
Capital = the whole buffer, where the lowercase is one hunk.

<leader>gs,gS   stage hunk (or the selected lines), buffer
<leader>gr,gR   reset hunk (or the selected lines), buffer
<leader>gp      preview hunk                    <leader>gq  hunks to quickfix
<leader>gQ      every changed file's hunks, open or not, to quickfix
<leader>gd      diff this file                  <leader>gD  every changed file
ih              the hunk as a text object: dih, yih

gs on a hunk that is already staged unstages it; the signs dim when staged,
so you can see which is which.

In the gutter: + added · ~ changed · ┆ untracked · ≃ changed and shortened.
Deleted lines are gone, so _ and ‾ mark the edge they went from: _ below
the gap, ‾ on line 1 when the gap is above it. Those three carry how many
lines went, 1-9 then > for more, since the lines are not there to count.

<leader>gb      blame this line, in a float
<leader>gB      blame the file, in a scroll-bound side panel
<leader>gl      line history: every commit that touched it (visual: the range)
<leader>gt      function history: the whole function, as it moved and changed
<leader>gf      file history: every commit touching the file, as a picker

gt needs the repository to have enabled git's funcname pattern for the
language (`*.py diff=python` in .gitattributes); it says so when it has not.
On a definition line prefer gt: gl there shows the signature and hides the
body that changed with it.

Inside the blame panel: <CR> menu · s,S show commit in a split, a tab
r reblame at that commit · R at its parent · d,D diff it in a tab
r and R land you in a read-only revision of the file: the statusline then
reads path[sha], as the pickers do. <C-o> comes back. They error across a
rename.

After :Gitsigns change_base X, the statusline reads X..branch: the signs and
counts now compare against X, as `git diff X` would. Staging and resetting
refuse until the base is the index again: a hunk against X is X's diff.

Its toggles are under <leader>ug, see |cheatsheet-toggles|. |gitsigns-usage|
has the plugin's own.

REVIEW MODE                                               *cheatsheet-review*

A branch the way its pull request shows it (bR develop...feature-x), or one
commit against its parent (cR feature-x~3 4/7). Writes refused, edits not.
All of it: |review-mode|.

<leader>uR      on or off                   :Review {ref}  against that ref
:Review @{u}    what is not pushed yet      <Tab>  the detected bases first
]v,[v           next, previous commit under review, checked out in turn
]c,[c           the hunks under review      <leader>gD  the changed files
<leader>gQ      every hunk, to quickfix     <leader>gd  this file vs the base

------------------------------------------------------------------------------
TOGGLES                                                  *cheatsheet-toggles*

<leader>u, for ui. Settings that switch, standard options and ours alike.

uw wrap · us spell · ul line numbers · ur relative numbers · ub light/dark
uh inlay hints
ud diagnostics written out: cursor line → every line (underlined) → none
uD diagnostics shown: all → warnings+errors → errors (signs always show all)
um markdown table alignment (on by default for markdown)
uH markdown heading colours (on by default for markdown)
uz fold column (see |cheatsheet-folds|)
uR review mode (see |cheatsheet-review|)
ua autosave: writes on leaving insert or the buffer, off by default
ug* git: ugd deleted lines · ugw word diff · ugb cursor-line blame
